# 지침 변경 뒤에도 하위 규칙이 빠지거나 출력이 잘리는 경우

## 증상과 확인된 한계

- 루트에서 시작해 모듈 지도를 읽어도 다른 모듈로 작업이 확대될 때 하위 `AGENTS.md` 본문을 누락할 수 있습니다. 링크·파일 목록을 보거나 모델이 규칙을 요약한 것만으로 본문 로딩과 실제 준수를 입증할 수 없습니다.
- 내부 실행 도구의 출력 한도를 늘려도 상위 도구 응답의 한도 때문에 실패 로그가 잘릴 수 있습니다. 테스트 성공이나 토큰 감소만으로 필요한 지침·오류를 모두 읽었다고 판단하지 않습니다.

## 진단과 대응

1. [지침 탐색 규칙](../../AGENTS.md#읽기-경로)에 따라 실제 수정 경로와 세션에 주입·조회된 지침을 대조합니다. 새로운 모듈의 첫 편집 전에 빠진 하위 지침을 읽고 해당 변경을 검토합니다. 단순 키워드 검색 결과와 본문 조회를 구분합니다.
2. 잘린 출력은 최종 응답 한도를 기준으로 누락 구간만 읽습니다. 긴 검사 로그는 임시 파일에 보존하고 종료 코드를 유지한 채 실패 요약을 출력하거나 기존 테스트 보고서의 관련 실패만 조회합니다. 세부 기준은 [검사 실행과 출력](../conventions/testing.md#검사-실행과-출력)을 따릅니다.
3. [새 세션 로딩 확인](../onboarding/README.md#에이전트-문서-탐색)과 실제 작업의 지침 준수를 따로 검증합니다. 누락이 반복되면 해결됐다고 보고하지 않고 수정 경로·본문 조회 여부·적용 행동을 근거로 남깁니다. 문구 보강만으로 준수가 자동 강제되지는 않습니다.

## 개선 효과를 비교할 때

- 같은 프롬프트도 모델의 설계 제안과 후속 승인에 따라 기능 범위가 달라집니다. 코드 기준점·완료 조건·모델·추론 수준·실행 방식·전역 목록을 맞추고, 테스트 개수 대신 실제 검증 범위를 비교합니다.
- 공유 worktree는 다른 브랜치의 과거 해법도 노출합니다. 이전 답안을 배제해야 하는 실험은 필요한 기준 이력만 가진 독립 저장소에서 실행하고 답안 재사용 실행은 비교에서 제외합니다.
- 요청별 고유 사용량을 집계하고 재개 시 누적 카운터를 중복 합산하지 않습니다. 캐시 입력·비캐시 입력·출력·압축을 구분하며 단일 실행의 감소율을 순수 세팅 효과나 비용 절감률로 단정하지 않습니다.
- 원본 로그·수치·실험 이력은 별도 산출물에 두고 이 문서에는 재사용 가능한 진단만 유지합니다.
