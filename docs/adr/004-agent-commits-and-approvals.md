# ADR-004: 에이전트의 자동 커밋과 실행 승인 경계

- 상태: Accepted
- 기준일: 2026-09-12
- 관계: [ADR-001](001-template-architecture.md)의 작업 지침·검증 원칙을 보완합니다. 기존 결정의 대체는 없습니다.
- 후속 보완: [ADR-005](005-work-loss-and-github-approvals.md)는 작업 손실·GitHub 승인 경계와 로컬 앱 DB 삭제의 적용을 명확히 합니다.
- 후속 보완: [ADR-007](007-commit-checkpoints.md)은 구현 전 단위 분리와 다음 변경을 시작하기 전 검증·커밋 체크포인트를 구체화합니다.

## 배경

기존 가이드는 이슈·PR 형식을 정의하지만 커밋 단위·시점·브랜치 운영은 정하지 않았습니다. 자동 개발을 허용하는 범위와 이력·데이터·외부 환경 변경에 대한 확인 범위를 구분해야 합니다. 테스트의 일회성 DB 정리도 삭제 전 확인 대상이라는 사용자 결정을 반영합니다.

## 결정

- 요청한 작업의 조회·DB 정리가 없는 로컬 검사·빌드, 필요한 소스 삭제·생성물 정리는 추가 승인 없이 수행합니다.
- 독립 변경 단위가 관련 집중 검사를 통과하면 새 커밋을 자동 생성합니다. 기본 브랜치에서는 작업 브랜치를 먼저 생성합니다. 작업 완료 시 기존 전체 검증을 수행하며, 커밋 금지 등 명시 요청은 자동 커밋보다 우선합니다.
- 커밋 메시지는 기존 PR 형식과 한국어 이력에 맞추고, 변경 목적·소유권·검증 가능한 단위로 묶습니다. 상세 작성·스테이징 기준은 [커밋 규칙](../conventions/github-workflow.md#커밋)이 소유합니다.
- 푸시·브랜치 삭제·DB 데이터/볼륨 삭제·배포·amend·rebase·reset은 사용자가 직접 요청해도 대상·변경 범위를 요약한 뒤 추가 확인받습니다.
- 테스트 전용 DB 자원 삭제에도 예외를 두지 않습니다. DB 검사는 생성·삭제를 포함한 실행 범위를 먼저 승인받습니다. 기존 CI의 실행 동작은 유지하며, 에이전트가 CI를 유발하는 작업의 요약에는 DB 테스트·정리도 포함합니다.
- 승인 대상 행위는 [루트 지침](../../AGENTS.md#작업-원칙), 승인에 필요한 정보는 [작업 가이드](../conventions/github-workflow.md#승인-절차), 검사 선택은 [테스트 문서](../conventions/testing.md)가 소유합니다.

## 적용과 제약

`.rules`는 명령 접두사에 대한 보조 정책이며, 작업 의도·변경 소유권·테스트 내부 SQL을 판별하지 않습니다. 포괄적인 `git`·`./gradlew` 허용으로 대화에서 정한 범위를 넓히지 않습니다. 정책 후보와 적용 한계는 [온보딩](../onboarding/README.md#실행-정책을-검토할-때)에 둡니다. 활성 규칙·승인 모드·sandbox 설정 변경은 이 기록만으로 수행하지 않습니다.

## 영향과 검증

중간 커밋을 통해 독립 변경을 보존하면서 전체 검증 의무를 유지합니다. DB 검사는 일회성 자원이라도 사용자 확인을 기다리므로 무인 로컬 전체 검증은 기본 동작이 아닙니다. 승인 없이 생략한 검사는 전체 통과로 보고하지 않습니다.

문서 간 원본·링크·승인 예외의 일치와 `git diff --check`를 확인합니다. 비활성 `.rules` 후보는 `codex execpolicy check`로 일치·비일치 사례를 검사하며 실제 명령 실행·정책 설치와 구분합니다. 제품 코드·의존성·CI는 변경하지 않습니다.
