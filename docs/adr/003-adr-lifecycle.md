# ADR-003: ADR 상태와 대체 이력 관리

- 상태: Accepted
- 기준일: 2026-09-12
- 대체 대상: [ADR-001](001-template-architecture.md)의 「목적과 범위」 중 단일 ADR을 계속 갱신하는 방식.

## 배경

후속 ADR을 추가해도 이전 문서가 Accepted 상태로 남아 있으면 어떤 결정이 현재 유효한지 알기 어렵습니다. 일부 결정의 변경을 전체 폐기로 표시하면 유지해야 할 모듈 경계·영속성 원칙까지 폐기된 것으로 읽힐 수 있습니다.

## 결정

새 결정은 별도 ADR로 기록하고 이전 결정의 본문은 이력으로 보존합니다. 기존 문서에는 상태와 변경일을 기록하고, 대체된 원문에 취소선과 후속 ADR 링크를 붙입니다. 유효한 문장은 그대로 둡니다.

전체 대체는 Superseded, 일부 대체는 Partially Superseded, 대체 결정 없는 사용 중단은 Deprecated로 구분합니다. 단순 보완은 Accepted를 유지합니다. 후속 결정이 Accepted가 될 때 양쪽 ADR과 색인을 함께 갱신합니다.

## 작성과 변경 규칙

- 새 구조·정책 결정은 다음 번호의 ADR로 추가합니다. 번호를 재사용하거나 과거 결정의 의미를 덮어쓰지 않습니다.
- 새 ADR에는 상태, 기준일, 배경, 결정, 영향·검증과 이전 ADR과의 관계를 기록합니다.
- 후속 ADR이 Accepted가 되면 이전 원문의 대체된 문장·구절만 `~~취소선~~`으로 감싸고 바로 뒤에 `(ADR-NNN로 대체)` 링크를 붙입니다. 유지되는 원칙이나 단순히 보완한 문장에는 취소선을 붙이지 않습니다.
- 예: ~~user·activity 예제를 사용합니다.~~ ([ADR-002로 대체](002-application-contracts-and-auth-example.md))
- 여러 항목을 대체하면 해당 항목마다 표시합니다. 상단에 긴 대체 범위 목록을 중복 작성하지 않습니다. 기존 문서의 상태·변경일·후속 링크는 짧게 유지합니다.
- 새 ADR에는 대체하는 이전 ADR을 연결하고, 어느 결정을 대체·보완하는지 명시합니다. 문서 번호가 크다는 이유만으로 이전 결정 전체를 폐기하지 않습니다.
- 후속 결정 없이 사용을 중단하면 해당 원문에 취소선과 `(Deprecated: 중단 이유, 날짜)`를 붙입니다. 일부만 중단하면 문서 전체를 Deprecated로 표시하지 않습니다.
- Proposed 단계에서는 기존 결정에 취소선을 붙이거나 대체 상태로 바꾸지 않습니다.
- README에는 현재 유효한 결정을 주제별로 요약하고 근거 ADR을 연결합니다. 과거 결정 목록·대체 이력·상세 작성 규칙은 원문에서 관리합니다.
- 오탈자·깨진 링크 수정과 상태·취소선·후속 링크 추가는 허용하며, 과거 결정 내용은 보존합니다.

## 상태

| 상태 | 의미 |
| --- | --- |
| Proposed | 검토 중이며 적용 결정 전 |
| Accepted | 적용 중인 결정 |
| Partially Superseded | 일부 결정만 후속 ADR로 대체됨 |
| Superseded | 결정 전체가 후속 ADR로 대체됨 |
| Deprecated | 후속 대체 결정 없이 사용을 중단함 |

## 적용 범위와 유지하는 결정

ADR-001의 단일 문서 갱신 방식을 대체합니다. ADR-002가 대체한 예제 구성·Application 분류와 나머지 아키텍처 원칙에는 영향을 주지 않습니다. ADR-001 본문의 과거 갱신 지시는 원문의 취소선과 후속 링크에 따라 적용하지 않습니다.

## 영향과 검증

문서를 열었을 때 현재 유효한 범위를 확인할 수 있고 결정 이유의 이력을 유지합니다. 이전·후속 문서와 색인을 함께 관리해야 합니다. 원문의 취소선 범위와 후속 결정의 일치, README의 현재 요약, 양방향 링크와 `git diff --check`로 검증합니다. 실행 코드에는 영향이 없습니다.
