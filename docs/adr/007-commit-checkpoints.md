# ADR-007: 리뷰 가능한 변경 단위와 작업 중 커밋 체크포인트

- 상태: Accepted
- 기준일: 2026-09-12
- 관계: [ADR-004](004-agent-commits-and-approvals.md)의 독립 단위 자동 커밋을 구체화합니다. 기존 결정의 대체는 없습니다.

## 배경

독립 변경마다 커밋한다는 원칙과 리뷰 묶음 약 500줄 기준만으로는 하나의 기능을 지나치게 큰 단위로 해석할 수 있습니다. 구현 전 분리와 다음 변경을 시작할 조건을 명확히 해야 합니다.

## 결정

- 여러 책임의 작업은 구현 전에 목적·파일 범위·의존성·집중 검사로 예정 커밋을 나눕니다.
- 한 단위를 구현·검증·검토한 뒤 즉시 커밋하고 다음 단위를 시작합니다. 코드 커밋은 필요한 테스트·설정·문서와 함께 컴파일·집중 검사 가능한 상태여야 합니다.
- 미커밋 변경이 약 500줄에 도달하기 전에 분리 가능성을 점검합니다. 초과가 필요한 결합은 계속 구현하기 전에 설명하며, 완결성을 깨는 기계적인 분할은 하지 않습니다.
- 집중 검사가 막히면 해당 단위의 변경 확대·커밋을 보류합니다. 삭제 없는 진단은 계속하고 다른 독립 변경은 작업 트리를 분리합니다.
- 전체 기능 완성 후 일괄 커밋을 기본으로 사용하지 않습니다. 전체 검증에서 발견한 수정은 별도 후속 커밋으로 남깁니다.

상세 절차의 원본은 [작업 중 커밋 체크포인트](../conventions/github-workflow.md#작업-중-커밋-체크포인트)입니다. [루트 지침](../../AGENTS.md#작업-원칙)은 진행 조건과 원본 링크를 유지합니다.

## 영향과 검증

커밋마다 의도와 검증 결과를 확인할 수 있도록 작업 중 진행 조건을 추가합니다. 사용자 커밋 금지 지시, 문서 전용 검증, 전체 검증 의무와 [승인 경계](../conventions/github-workflow.md#승인-절차)는 유지합니다. 커밋 분리가 PR 분리 기준을 대체하지 않습니다.

문서 링크·앵커·정책 일관성과 `git diff --check`를 확인합니다. Git hook·CI·도구 권한을 변경하지 않으므로 자동 강제 장치가 생기는 것은 아닙니다.
