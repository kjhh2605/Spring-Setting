# ADR-005: 작업 손실과 GitHub 변경의 승인 경계

- 상태: Accepted
- 기준일: 2026-09-12
- 관계: [ADR-004](004-agent-commits-and-approvals.md)를 보완합니다. 기존 결정의 대체는 없습니다.

## 배경

이력 재작성·DB 삭제 외에도 미커밋 작업이나 stash를 잃는 명령이 있습니다. GitHub 작성과 병합·게시의 승인 범위도 구분할 필요가 있어 사용자 인터뷰로 추가 경계를 확정했습니다. 현재 `local`의 `create-drop`은 테스트 외 앱 실행에도 기존 DB 삭제 승인이 필요함을 보여 줍니다.

## 결정

- 미커밋·보관한 작업을 잃는 Git 정리·복원은 사용자가 요청해도 대상·손실 내용을 요약한 뒤 추가 확인받습니다. 요청에 필요한 소스 삭제·생성물 정리와 조회·미리보기는 자동 범위를 유지합니다.
- PR 병합·닫기·삭제와 릴리스 게시는 요약 후 추가 확인받습니다. 요청한 PR·이슈 생성·수정·댓글은 추가 확인 없이 수행하며, 요청 없이 게시하지 않습니다. 동반하는 푸시·DB 삭제 등 기존 승인 경계는 유지합니다.
- `create-drop` 등 앱 내부 스키마 삭제는 실행·종료를 포함해 사전 승인받습니다. 실행 명령·프로필·대상 DB를 확인하며, 로컬이라는 이유로 삭제 승인을 생략하지 않습니다.
- 승인 대상 요약은 [루트 지침](../../AGENTS.md#작업-원칙), 구분과 전달 정보는 [승인 절차](../conventions/github-workflow.md#승인-절차)가 소유합니다.

## 영향과 검증

작업 손실과 외부 반영 전에 확인하면서 일상적인 작성·생성물 정리는 자동으로 유지합니다. 명령 접두사는 손실 여부·프로필·게시 여부·임의 옵션 순서를 판별하지 못하므로 [실행 규칙의 적용과 한계](../onboarding/README.md#실행-정책을-검토할-때)를 구분합니다. 이 결정만으로 활성 설정·sandbox·승인 모드를 변경하지 않습니다.

문서 링크·경로·정책 일관성과 `git diff --check`, 후보의 일치·비일치 사례를 검사합니다. 규칙 평가는 대상 명령 실행이나 실제 승인 UI 검증을 의미하지 않습니다. 제품·의존성·CI 동작은 유지합니다.
